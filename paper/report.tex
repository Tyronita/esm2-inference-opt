\section{Method: All Scoring Strategies}

\subsection{Masked Marginal Scoring (canonical baseline)}

Masked marginal scoring~\cite{meier2021language} isolates each mutated
position by replacing it with the \texttt{[MASK]} token, then reads off
the model's probability for the wildtype and mutant residues.

\begin{equation}
  \text{Score}(\mathbf{x}, \mathcal{M}) =
    \sum_{i \in \mathcal{M}}
    \Bigl[
      \log p\!\left(x^*_i \mid \mathbf{x}_{-i}\right)
      -
      \log p\!\left(x_i \mid \mathbf{x}_{-i}\right)
    \Bigr]
  \label{eq:masked}
\end{equation}

where $\mathbf{x}_{-i}$ is the wildtype sequence with position $i$ replaced
by \texttt{[MASK]}.  Each term is a log-likelihood ratio: positive means the
model prefers the mutant.

Cost: $|\text{unique mutated positions}| \leq L$ forward passes per assay.
For an $L$-residue protein, total cost scales as $\mathcal{O}(L^2)$.

\paragraph{Key insight from A100 results.}
Pseudo-perplexity and masked marginals produce \emph{identical} Spearman $\rho$
for single-site variants (SNCA: $\rho=+0.137$ both; PRKN: $\rho=+0.501$ both)
but pseudo-perplexity is 18--65$\times$ slower
(SNCA: 65.6\,s vs 3.7\,s; PRKN: 235\,s vs 12.8\,s).
The extra passes score $N$ mutant sequences instead of the $L$
masked WT copies, giving $N/L$ overhead with no information gain for
single-site variants.

\section{ProteinGym Benchmark}

ProteinGym~\cite{notin2023proteingym} is a large-scale collection of
deep mutational scanning (DMS) assays.
We use the \textbf{substitution benchmark}: 217 assays, $\sim$2.5M total
variants, covering diverse proteins and fitness phenotypes.

\paragraph{Metric.}
Spearman rank correlation $\rho_s$ between predicted scores and
experimental fitness, averaged over all 217 assays.
Rank correlation is invariant to monotone rescaling of fitness values,
which vary widely across assays.

\paragraph{Published baseline.}
ESM-2 650M with masked marginals: $\rho = 0.414 \pm 0.012$
(mean $\pm$ bootstrap SE, 217 assays)~\cite{notin2023proteingym}.

\paragraph{PD-relevant assays in the benchmark.}
Note: LRRK2 and GBA are \emph{not} in the 217-assay set.

\begin{itemize}[nosep]
  \item \texttt{SYUA\_HUMAN\_Newberry\_2020} — $\alpha$-synuclein (SNCA),
        $L{=}140$, 2497 variants. Direct PD relevance: A53T, E46K, A30P.
  \item \texttt{PRKN\_HUMAN\_Clausen\_2023} — Parkin (PARK2),
        $L{=}465$, 8756 variants. PD gene 2.
  \item \texttt{BRCA1\_HUMAN\_Findlay\_2018} — BRCA1, $L{=}1863$.
        Long-sequence windowing test.
  \item \texttt{A0A140D2T1\_ZIKV\_Sourisseau\_2019} — ZIKV NS5, $L{=}3423$.
        Longest assay; $L^2$ cost stress test.
\end{itemize}

\section{Empirical Timing Model}

\begin{equation}
  t(L) \approx
  \begin{cases}
    \hat{\beta} \cdot L^2 & L \leq 1022 \\[4pt]
    \hat{\beta}' \cdot L  & L > 1022
      \quad\text{(windowing: each pass costs }\mathcal{O}(1022)\text{ tokens)}
  \end{cases}
  \label{eq:timing}
\end{equation}

$\hat{\beta}$ is fitted live during each run:
$\hat{\beta} = \mathrm{median}\!\left(\{w_i / L_i^2\}_i\right)$
where $w_i$ is the wall-clock time for assay $i$.
Implemented in \texttt{benchmark/timing.py::RunTimer}.

\section{Integrity \& Story System}

\subsection{Append-only story log}

Every git commit auto-appends one entry to \texttt{STORY.md} via
\texttt{.githooks/post-commit}. Each entry records:

\begin{itemize}[nosep]
  \item Commit SHA, author, timestamp
  \item Human narrative of what changed and why
  \item Files and line counts
  \item Integrity snapshot: Merkle root $+$ submodule SHAs
  \item Exact \lstinline|git revert <sha> --no-edit| cleanup command
\end{itemize}

Method run results are also appended (\texttt{scripts/story.py --append-results})
after each \texttt{pull\_results} call, adding one story section per
method with per-assay $\rho$ and $\beta$.

\subsection{Pre-commit source guard}

\texttt{.githooks/pre-commit} blocks any commit that stages changes
inside \texttt{refs/fair-esm/} or \texttt{refs/ProteinGym/}.
These directories must remain byte-identical to the pinned SHAs.
Submodule pointer changes warn but do not block (may be an intentional
SHA bump).

\subsection{Verify at any time}

\begin{lstlisting}[style=shell]
python benchmark/verify_integrity.py  # Merkle root + per-file SHA256
python benchmark/verify_integrity.py --verbose  # print every file hash
python check_consistency.py           # live score comparison
python scripts/story.py --check       # dry-run next story entry
\end{lstlisting}
